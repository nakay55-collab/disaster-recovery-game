# PROJECT2 チームクイズ

土木会社の合同企業説明会で、「災害復旧・まちづくりゲーム」PROJECT2の開始前に使うチーム対抗クイズです。約20名・4人×5チームを想定し、チームごとにタブレットまたはスマートフォン1台で、相談しながら8問に回答します。正解数に応じてPROJECT2で使う重機カード・人カードを獲得します。外部ライブラリ・外部フォント・ビルド・サーバー側処理は不要です。

初回個人クイズ（`initial-civil-quiz`）と同じ配色・雰囲気（白・グレー・黄色・オレンジ）で作っていますが、このフォルダは独立しており、初回個人クイズのファイルには一切手を加えていません。

## ファイル

- `index.html`：画面の土台と終了確認ダイアログ
- `style.css`：スマートフォン縦画面を優先しつつ、タブレット横画面でも見やすいレスポンシブデザイン
- `script.js`：問題データ、設定、タイマー、保存、採点、カード配布枚数
- `README.md`：起動・運用・変更方法

## PCで起動

`index.html` をブラウザで開けば動作します。保存の挙動を安定させるため、当日の事前テストにはHTTPでの起動を推奨します。Python 3が使える場合、このフォルダで次を実行してください。

```sh
python3 -m http.server 8001 --bind 0.0.0.0
```

初回個人クイズ用のサーバー（ポート8000）と同時に動かせるよう、ポート番号を8001にしています。PCで `http://localhost:8001/` を開きます。停止はターミナルで Ctrl+C。最近のSafari・Chrome・Edge・Firefoxを想定しています。

## スマートフォン・タブレットでテスト

1. PCとスマートフォン・タブレットを同じWi-Fiにつなぎます。
2. 上記のサーバーを起動します。
3. PCのネットワーク設定でWi-FiのローカルIPアドレスを確認します。
4. スマートフォン・タブレットで `http://192.168.1.10:8001/` のように開きます（IPは実際のPCの値に置換）。`localhost` は使いません。
5. 接続できない場合はPCのファイアウォール設定とWi-Fiの端末間通信制限を確認します。PCは起動したままにします。

当日はチームごとに1台の端末で開く想定です。公開HTTPS URLを用意できればQRコードでの配布もできます（下記「Web公開とQRコード」参照）。

## 変更する場所

`script.js` 冒頭に設定をまとめています。

- 問題文・選択肢・正解・解説：`QUESTIONS` 配列の `text`、`options`、`correct`、`explanation`。正解はA=0、B=1、C=2、D=3です。`explanation` は結果画面の「答えを見る」で表示する短い解説です。
- 5分タイマー：`CONFIG.durationSeconds: 5 * 60`。秒数です。短時間の動作確認なら `15` などに変更し、管理者リセット後に開始してください。本番前に `5 * 60` に戻します。
- カード配布枚数：`CARD_TIERS` の `minCorrect`・`heavyCards`（重機カード）・`peopleCards`（人カード）・任意の `message`（最上位のみ「すばらしい！」を設定）。`minCorrect` の大きい順に並べ、最後は0にしてください。初期値は次の通りです。
  - 7〜8問正解：重機5枚＋人2枚（「すばらしい！」）
  - 5〜6問正解：重機4枚＋人2枚
  - 3〜4問正解：重機3枚＋人2枚
  - 0〜2問正解：重機2枚＋人2枚
- 選べるカードの種類：`HEAVY_CARD_TYPES`（重機カード）・`PEOPLE_CARD_TYPES`（人カード）。結果画面に一覧表示するだけで、このシステム内では在庫・枚数の管理はしません（紙のカードをスタッフが手渡しします）。
- 保存データの識別：`CONFIG.storageKey`。問題構成を変えた際は `v2` などに変更し、旧問題の回答が混在しないようにします。

## 進行と保存

- スタート画面の「クイズスタート」を押した瞬間から5分後の終了時刻を保存します。8問全体で共通の制限時間です。
- 選択直後に保存するので、「次へ」を押す前の選択も採点対象です。
- 回答中は正解・不正解を表示しません。未回答で次へ進むと「回答を選んでください」と表示します。戻る操作でチームの回答を修正できます。
- 最終問題の「回答を終了する」で確認を表示し、確定後に採点します。確認中も時間は進み、時間切れが優先されます。
- 残り60秒で黄色系の強調、10秒で赤い強調になります。0秒でTIME OUTを表示し、未回答は不正解になります。
- 結果画面では正解数・獲得カード枚数・選べるカードの種類を中心に表示し、「答えを見る」を押した場合のみ、各問題の問題文・チームの回答・正解・短い解説を確認できます。
- 同じ端末・同じURLの配信元で、回答・表示問題・終了時刻・終了状態をlocalStorageに保持します。再読み込みやタブを閉じた後も復元し、タイマーは5分に戻りません。バックグラウンドから戻った際には実時刻で期限を確認します。
- 終了後は戻る・回答変更・通常の再挑戦はできません。同じ配信元の別タブにも保存変更を通知します。
- 保存できない環境では警告を表示します。その場合、再読み込みでの復元はできません。

## 管理者リセット

通常URLではリセットボタンを表示しません。スタッフが同じ端末で次のURLを開くと、ページ下部に「管理者用：リセット」が表示されます。

```text
http://localhost:8001/?admin=1
https://公開先のURL/?admin=1
```

確認してリセットすると、その端末の回答と結果を初期化し、スタート画面に戻ります。他の端末（他チーム）には影響しません。チーム用QRコードには `?admin=1` を含めないでください。同じタブレットを複数チームで使い回す場合は、チームが交代するたびにスタッフがリセットし、通常URLに戻してください。

これは簡易的な再挑戦防止であり、管理者認証ではありません。JavaScript内の正解閲覧、保存データ削除、別ブラウザ・プライベートモード、端末時計変更などによる不正を完全には防げません。厳密な制限が必要になった場合は、チームごとの識別とサーバー側での採点・期限管理を追加します。回答は端末内だけに保存され、スタッフ向け集計や個人情報送信はありません。

## Web公開とQRコード

1. 4ファイルを同じフォルダ構成のまま静的Webホスティングへ配置します。`index.html` と同じ場所の `style.css`・`script.js` が読み込めるようにします。
2. 公開HTTPS URLを確定し、ログインなしでアクセスできることを確認します。
3. **管理者パラメータのない公開URL**をQRコードにします。チームごとの配布物に印刷し、予備として短いURLも記載します。
4. 実際のスマートフォンとタブレット（縦・横どちらも）でQR読み取り、文字サイズ、回答、結果表示を確認します。
5. 会場のWi-Fiまたは携帯回線で接続確認をします。5チーム分の回答処理は各端末内で動きます。最初のページ読み込みには通信が必要です。

公開先の契約・アカウント設定、ファイルのアップロード、公開URL確定、QRコードの作成は別途必要です。このフォルダだけではインターネット上には公開されません。

## 当日前の確認項目

- 8問すべて表示されること。
- 制限時間5分が正しく動くこと。
- 再読み込みしてもタイマーが5分に戻らないこと。
- 未回答の問題が時間切れ時に不正解として扱われること。
- 8問正解・7問正解でどちらも重機5枚＋人2枚（合計7枚）になること。
- 6問正解・5問正解でどちらも重機4枚＋人2枚（合計6枚）になること。
- 4問正解・3問正解でどちらも重機3枚＋人2枚（合計5枚）になること。
- 2問以下の正解で重機2枚＋人2枚（合計4枚）になること。
- 「答えを見る」で問題・チームの回答・正解・短い解説が確認できること。
- スマートフォンの狭い画面でも表示が崩れないこと（タブレット横画面では選択肢が2列になります）。
- 終了後の再読み込みでも結果が残り、通常URLにリセットがないこと。
- 管理者リセット後にスタート画面へ戻り、新しく開始できること。

# 災害復旧チャレンジクイズ（初回個人クイズ）

土木会社の合同企業説明会で、災害復旧・まちづくりゲームの最初に使う個人クイズです。スタート画面で「10問に挑戦」「13問に挑戦」のどちらかを選び、「クイズスタート」を押した瞬間から8分の共通タイマーが始まります。外部ライブラリ・外部フォント・ビルド・サーバー側処理は不要です。

高校1〜2年生が初見で回答することを想定し、13問版で平均7点前後になる難易度を狙っています（重機の名称だけでなく、資格・安全確認・工程判断・会社としての総合判断の問題を含みます）。

## ファイル

- `index.html`：画面の土台と終了確認ダイアログ
- `style.css`：スマートフォンを優先したレスポンシブデザイン
- `script.js`：問題データ、設定、タイマー、保存、採点、カード判定
- `README.md`：起動・運用・変更方法

## PCで起動

`index.html` をブラウザで開けば動作します。保存の挙動を安定させるため、当日の事前テストにはHTTPでの起動を推奨します。Python 3が使える場合、このフォルダで次を実行してください。

```sh
python3 -m http.server 8000 --bind 0.0.0.0
```

PCで `http://localhost:8000/` を開きます。停止はターミナルで Ctrl+C。最近のSafari・Chrome・Edge・Firefoxを想定しています。

## スマートフォン・タブレットでテスト

1. PCとスマートフォンを同じWi-Fiにつなぎます。
2. 上記のサーバーを起動します。
3. PCのネットワーク設定でWi-FiのローカルIPアドレスを確認します。
4. スマートフォンで `http://192.168.1.10:8000/` のように開きます（IPは実際のPCの値に置換）。スマートフォン側で `localhost` は使いません。
5. 接続できない場合はPCのファイアウォール設定とWi-Fiの端末間通信制限を確認します。PCは起動したままにします。

端末のカメラからの動作も確認する場合は、このテスト用URLのQRコードを作成します。ローカルIPのURLは同じネットワーク内でのみ使えます。当日は公開HTTPS URLを使用する方が扱いやすくなります。

## 変更する場所

`script.js` 冒頭に設定をまとめています。

- 問題文・選択肢・正解：`QUESTIONS` 配列の `text`、`options`、`correct`。正解はA=0、B=1、C=2、D=3です。`QUESTIONS` には13問すべてを1回だけ記載し、10問版・13問版のどちらもこの配列から出題を組み立てます（同じ問題を重複して書きません）。
- 10問版の出題内容：`TEN_QUESTION_IDS`（初期値 `[1, 2, 3, 4, 5, 6, 7, 8, 9, 12]`）。この配列に書いたQUESTIONSの番号（1始まり）を、書いた順番で出題します。10問版だけ入れ替えたい場合はこの配列を変更してください。13問版は常に`QUESTIONS`全問をQ1〜Q13の順に出題します。
- コースの選択肢：`COURSE_OPTIONS`。初期値は `[10, 13]` です。
- 終了後の解説：問題の `explanation`。現在は3t未満／3t以上の資格を問うQ4・Q5のみ設定しています。回答中は表示せず、結果画面の「答えを見る」を開いたときだけ表示します。
- 8分タイマー：`CONFIG.durationSeconds: 8 * 60`。秒数です。短時間の動作確認なら `15` などに変更し、管理者リセット後に開始してください。本番前に `8 * 60` に戻します。どちらのコースを選んでも同じ制限時間です。
- カード判定・内容：`CARD_SETS` は10問版・13問版で共通の1つの配列です（`minCorrect` の大きい順、最後は0）。初期値はA=11以上、B=8以上、C=5以上、D=0以上です。10問版はここを変更する必要はありません（下記「10問版の採点」を参照）。

### 10問版の採点（13点満点への換算）

10問版だけの別ルールは作らず、正解数を13点満点相当に換算してから13問版と同じ`CARD_SETS`で判定します（`judgingScore`関数、`script.js`内）。

```
換算点 = 正解数 ÷ 10 × 13
```

四捨五入はせず、小数のまま`CARD_SETS`の`minCorrect`と比較します（例：9問正解→11.7点相当→A、6問正解→7.8点相当→C）。結果画面には実際の正解数（例：「10問中7問正解」）だけを表示し、換算点は生徒には表示しません。

## 進行と保存

- スタート画面で問題数（10問／13問）を選ぶと選択ボタンがハイライトされ、「クイズスタート」ボタンが押せるようになります。押した瞬間に8分後の終了時刻を保存し、クイズが始まります。
- 選んだ問題数は、以降の画面上部に「3 / 10」「3 / 13」のように常に表示します。
- 選択直後に保存するので、「次へ」を押す前の選択も採点対象です。
- 回答中は正解・不正解を表示しません。未回答で次へ進むと「回答を選んでください」と表示します。戻る操作で回答を修正できます。
- 最終問題の「回答を終了する」で確認を表示し、確定後に採点します。確認中も時間は進み、時間切れが優先されます。
- 残り60秒で黄色系の強調、10秒で赤い強調になります。0秒でTIME OUTを表示し、未回答は不正解になります。
- 結果画面では正解数とカードセットを中心に表示し、「答えを見る」を押した場合のみ各問題の正解（と設定されていれば短い解説）を確認できます。
- 同じブラウザ・同じURLの配信元で、選んだ問題数・回答・表示問題・終了時刻・終了状態をlocalStorageに保持します。再読み込みやタブを閉じた後も復元します。バックグラウンドから戻った際には実時刻で期限を確認します。
- 終了後は戻る・回答変更・通常の再挑戦はできません。同じ配信元の別タブにも保存変更を通知します。
- 保存できない環境では警告を表示します。その場合、再読み込みでの復元はできません。

## 管理者リセット

通常URLではリセットボタンを表示しません。スタッフが同じ端末で次のURLを開くと、ページ下部に「管理者用：リセット」が表示されます。

```text
http://localhost:8000/?admin=1
https://公開先のURL/?admin=1
```

確認してリセットすると、そのブラウザの回答と結果を初期化し、問題数選択画面に戻ります。他の端末には影響しません。学生向けQRコードには `?admin=1` を含めないでください。共用タブレットは学生が交代する際にスタッフがリセットし、通常URLに戻してください。

これは簡易的な再挑戦防止であり、管理者認証ではありません。JavaScript内の正解閲覧、保存データ削除、別ブラウザ・プライベートモード、端末時計変更などによる不正を完全には防げません。厳密な制限が必要になった場合は、参加者ごとの識別とサーバー側での採点・期限管理を追加します。回答は端末内だけに保存され、スタッフ向け集計や個人情報送信はありません。

## Web公開とQRコード

1. 4ファイルを同じフォルダ構成のまま静的Webホスティングへ配置します。`index.html` と同じ場所の `style.css`・`script.js` が読み込めるようにします。
2. 公開HTTPS URLを確定し、ログインなしで学生がアクセスできることを確認します。
3. **管理者パラメータのない公開URL**をQRコードにします。配布物に印刷し、予備として短いURLも記載します。
4. 実際のスマートフォンとタブレットでQR読み取り、文字サイズ、回答、結果表示を確認します。
5. 会場のWi-Fiまたは携帯回線で接続確認をします。約20名の回答処理は各端末内で動きます。最初のページ読み込みには通信が必要です。

公開先の契約・アカウント設定、ファイルのアップロード、公開URL確定、QRコードの作成は別途必要です。このフォルダだけではインターネット上には公開されません。

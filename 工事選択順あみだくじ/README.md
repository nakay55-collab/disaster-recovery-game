# 5チーム用 あみだくじツール

土木会社の合同企業説明会「災害復旧・まちづくりゲーム」のPROJECT2・PROJECT3で、チームの「工事を選ぶ順番」を公平に決めるためのツールです。5チームまたは4チームを選べます。工事そのものの自動割り当てはせず、あくまで選ぶ順番（1番目〜最後）だけを決めます。他のクイズツール類とは別の独立したフォルダで、既存のファイルには一切手を加えていません。外部ライブラリ・外部フォント・ビルド・サーバー側処理は不要です。

進行役（先生・スタッフ）がタブレットやPCで操作し、結果画面はプロジェクターに映して生徒全員に見せる想定です。

## ファイル

- `index.html`：画面の土台とリセット確認ダイアログ
- `style.css`：PC・タブレットの横画面を優先しつつ、スマートフォンでも操作できるレスポンシブデザイン
- `script.js`：あみだくじの生成・進行ロジック、チーム・色・速度などの設定
- `README.md`：起動・運用・変更方法

## 全体の流れ

1. **PROJECT選択**：PROJECT2かPROJECT3を選ぶ。
2. **チーム数選択**：5チームか4チームかを選ぶ。4チームを選ぶと、初期値の赤・青・黄・緑チームが表示されます（白チームは含まれません）。
3. **チーム名変更**：選んだ人数分のチームの名前を必要に応じて変更する。
4. **順位入力**：現在の順位（1位〜最後）をチームごとに指定する。順位選択のとなりに、選んだチームの色が分かるスウォッチも表示される。PROJECT3のみ、入口を選ぶ順番を「上位から選ぶ」「下位から選ぶ」で切り替えられる（初期値は下位から）。
5. **入口選択**：決まった順番でチームが1人ずつ、あみだくじの入口を選ぶ。一度選ばれた入口は他のチームは選べない。
6. **くじを作る／あみだスタート**：ランダムなあみだくじを生成し、スタートすると各チームのルートが上から下へゆっくりたどられ、結果が表示される。
7. **結果**：「1番目・2番目…」の形で工事を選ぶ順番が大きく表示される（プロジェクター表示を想定）。

「あみだスタート」を押すと、チーム名・入口の変更はできなくなります（誤操作防止）。やり直したい場合は、画面右上の「リセット」から確認のうえ最初に戻ります。

## PROJECT2とPROJECT3のルールの違い

- **PROJECT2**：入力した順位の1位のチームから順に入口を選びます（常に上位から。切り替えはありません）。
- **PROJECT3**：標準では5位のチームから順に入口を選びます（下位からの逆転チャンス）。順位入力画面の「上位から選ぶ」「下位から選ぶ」ボタンで、その場で切り替えられます。

## 変更する場所

`script.js` 冒頭の `CONFIG` にまとめています。

- 選べるチーム数：`CONFIG.teamCountOptions`（初期値`[5, 4]`。表示順もこの並びです）
- 初期チーム名：`CONFIG.initialTeamNames`（5チーム分。4チーム選択時は先頭から4つを使用します）
- チームの色：`CONFIG.teamColors`（`initialTeamNames`と同じ並び順のHEXカラー）。白などの明るい色は、スウォッチ・入口の丸印・あみだくじのルート線すべてで自動的に濃い枠線や縁取りが付き、見失いにくくなっています。
- あみだくじの段数：`CONFIG.ladderRows`（多いほど見た目が複雑になります）
- アニメーションの速さ：`CONFIG.animationDurationMs`（ミリ秒。3000〜5000を推奨）
- PROJECT3の入口選択順の初期値：`CONFIG.defaultProject3PickOrder`（`"bottom-first"`＝下位から、`"top-first"`＝上位から）
- 保存データの識別：`CONFIG.storageKey`。チーム数などの構成を変えた際は`v3`などに変更してください。

## あみだくじの仕組みと公平性について

`generateLadder`関数が、隣り合う縦線だけをつなぐ横線（隣接ルール）を、同じ段で重ならないように段ごとにランダム生成します。「くじを作る」を押すたびに新しい形が作られ、まったく横線がない（何も起きない）くじになった場合は自動的に作り直します。各段の横線パターンは、そのチーム数で考えられる有効な組み合わせをすべて洗い出したうえで均等に1つを選んでいるため、左右どちら側かで偏った選ばれ方はしません。

ただし、これだけでは「端の入口ほど元の位置に近い場所に着地しやすい」という統計的な偏りが、段数が少ないあみだくじには構造的に残ります（これは境界効果と呼ばれる性質で、段数を増やしても完全にはなくなりません）。そこで、あみだくじの下に表示する「1・2・3…」の番号を**どの物理的な列に割り当てるかも「くじを作る」のたびにランダムにシャッフル**しています。これにより、あみだくじ自体にどんな偏りがあっても、どの入口を選んでも最終順位（1位〜最後）は数学的に均等な確率になります（10000回のシミュレーションで、どの入口も各順位にほぼ20%前後で到達することを確認済みです）。

各チームの最終順位は、選んだ入口から下まで実際にルートをたどって決まる正真正銘のあみだくじ計算です（見た目の演出だけでなく、結果もこのルートに基づきます）。縦線は必ずすべての出口にちょうど1つずつ対応するため、結果が重複したり空欄になったりすることはありません。

あみだくじの下には、シャッフルされた「1・2・3…」の番号を、準備画面の時点から常に表示しています。ルートが伸びる演出の間もこの番号だけは先に見えているので、「自分のチームの色がどの番号に向かっているか」を追いながら見られ、確定と同時に番号の下にチーム名が浮かび上がります。番号の並びは「くじを作る」「もう一度」を押すたびに、あみだくじの形と一緒に新しく決まり直します。

ルートが伸びる演出は、CSSに任せきりにせず毎フレームJavaScriptで位置を計算しており、線の先端に丸い目印を表示しながら実際に色が進んでいく過程を追えるようにしています。白などの明るい色は、線と同じ速さで伸びる濃い縁取りも一緒に表示されるため、結末が演出の途中で先に見えてしまうことはありません。

## 保存

誤って再読み込みしても、選択したPROJECT・チーム名・現在順位・入口選択順ルール・入口の選択状況・作成したあみだくじ・結果を、その端末のlocalStorageから復元します。アニメーションの演出中に再読み込みした場合は、演出を再生せずに確定済みの結果をそのまま表示します。

「リセット」を押すと確認ダイアログが表示され、「リセットする」を選ぶとこれらの保存内容がすべて削除され、PROJECT選択画面に戻ります。
